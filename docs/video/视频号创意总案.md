# 视频号创意总案（最优综合稿）

> 版本：v1.0 · 2026-08-02
> 综合 `docs/video/` 下 5 份方案的全部优点与创意，为唯一执行依据。
> 配套文档：《上岸·最终产品方案.md》（§9 内容飞轮）。

---

## 0. 一句话总纲

**不拍学习，拍"用工具打怪"；不拍过程，拍"数据与反馈"。**
你拍的不是学习 vlog，是一个程序员与自研学习系统的**交互日志**——这件事只有你能做。

---

## 1. 定位：连续剧，不是知识号

你不是"老师讲公考"（赛道挤、你没权威优势），而是：

> **一个普通上班族，用自己开发的 AI 公考系统坚持备考，全程记录从普通人到上岸。**

这个定位天然有**连续剧属性**——观众追的不是某道题，而是四个悬念：

1. 你能不能坚持？
2. 软件到底有没有用？
3. 方法有没有效果？
4. **最后到底能不能上岸？**

**三感原则**：真实感（乱中有序、有叹气有失误）+ 系统感（数据、图表、闭环）+ 成长感（正确率曲线、倒计时）。

**人设红线**：不装大神、不装老师、不鸡血、不卖课话术。优势就一句："我也是考生，我和大家一起成长。"

**账号名**：与 App 名联动，如「上岸日记」「程序员考公日记」。
**签名档**：公考程序员，每日一测。Bug 要修，题也要刷。

## 2. 视觉系统：一个固定场景，百变内容

背景是个人符号。观众一看到画面就知道是你。

### 2.1 场景：程序员的作战指挥台

- **固定桌面位**（90% 场景）：只清理出 40cm×40cm 区域，保留三样——开着 App 的手机/平板 + 草稿纸（要有涂改痕迹）+ 一杯水。桌面乱不要紧，**乱中有序才是备考人的真实状态**。
- **背景墙（记忆点软装）**：贴两张 A4 纸——「今日 Bug：0」和「上岸倒计时：XX 天」（倒计时随视频更新，本身就是连续剧线索）；或便利贴拼「上岸」二字。
- **灯光**：关顶灯。主光源 = 屏幕光；屏幕后贴一条 LED 暖光灯带照亮背景墙制造景深。"深夜台灯聚光灯"质感拉满。
- **禁忌**：床铺衣物入镜、强烈反光、品牌 logo 墙。

### 2.2 机位（固定不动，拒绝运镜）

| 机位 | 设置 | 用途 |
|------|------|------|
| **A 主视角：45° 俯拍** | 支架固定桌面斜上方，拍到屏幕 + 手 + 水杯 | 刷题/写笔记，代入感最强 |
| **B 纯录屏** | 手机/电脑录屏 | 软件演示，90% 时间的画面主体 |
| **C 侧拍氛围** | 手机立在屏幕旁，拍侧脸+屏幕 | 延时摄影、"双重努力"画面 |
| D 画中画 | 录屏为主 + 角落小窗（手/表情） | 剪辑时合成，画龙点睛 |

**创新锚点**：支架位置、高度永远不变——观众会记住"这个学习角落"。

### 2.3 时长（严格卡死，保护精力）

| 类型 | 时长 |
|------|------|
| **每日刷题记录（主力）** | **25–40 秒，目标 35 秒** |
| 方法拆解 | 45–60 秒 |
| 周总结/里程碑 | 60–90 秒 |
| 深度内容（偶尔，B 站向） | 3–5 分钟 |

## 3. 听觉系统：ASMR 思维

### 3.1 BGM

- **三不原则**：不抒情、不嘈杂（无人声）、不随意换。
- **风格**：Lo-fi Hip Hop（首选，自带"程序员熬夜刷题"的冷静感）/ 极简氛围电子。
- **音量**：10–20%，永远不盖人声。
- **双 BGM 体系（创意点）**：固定两首——**高正确率日用轻快版，错题复盘日用舒缓版**。观众听声音就知道你今天状态如何。

### 3.2 实景音效（比 BGM 更抓人）

鼠标点击声、机械键盘声、答对"叮"、答错低沉音、红笔批改"唰唰"声、翻书声。**保留不完美原声**（叹气、笔掉桌上）——真实感来源。

## 4. IP 符号系统（前 3 秒=你的指纹）

### 4.1 固定开场（选一个，绝不换）

**主推·数据型**：
- 画面：软件刷题首页
- 字幕大字：**「第 XX 天 · 正确率 XX%」**
- 口播：**「备考第 XX 天，开始今日刷题。」**

**视觉锤开场（动作版，可叠加）**：黑屏 → 按下台灯开关（灯亮）→ 按下计时器"开始" → 切入刷题。每天同一根手指点屏幕，形成视觉锚点。

### 4.2 固定结尾

> 「记录每天一点进步，希望明年的自己感谢现在的坚持。」
> 短版：「今天完成，明天继续。」/「如果你也在备考，我们一起坚持。」

### 4.3 代码注释流字幕（最强辨识度创意）

画面正常刷题/写代码，字幕像代码注释一样飘过：

```
// 今日状态：疲惫
// 资料分析错题：3 道
// 原因：单位没看清
// 方案：明天加强审题
return "明天继续";
```

零口播成本、人设浓度最高——**每周至少用 1–2 次**。

### 4.4 封面模板

统一版式：左/下 = 软件界面或实拍，右/上 = 三个大字标题（「AI批改」「周末挑战」「错题死磕」）+ 小字「第 XX 天 · 正确率 XX%」。剪映存模板，每天只换字。

## 5. 内容体系：三模式 + 每周配比

日常内容只做三种模式，按当天刷题情况选一种，不费脑：

| 模式 | 内容 | 频率 | 记录点 |
|------|------|------|--------|
| **模式1 正常刷题流** | 做题过程 + 最终正确率 | 每周 4–5 天 | 顺不顺、正确率 |
| **模式2 错题复盘流** | 错题特写 + 为什么错 + 如何闭环 | 每周 1–2 天 | 坑在哪、怎么防 |
| **模式3 专项突破流** | 进专项 → 计时做题 → 前后对比 | 每周 1 天 | 正确率提升曲线 |

**每周结构**：日更 5–7 条（主力三模式）+ 周日 1 条周总结（周报卡数据出镜）+ 每月 1–2 条方法拆解/产品故事。

**内容支柱（长期配比）**：每日记录 60% / 方法拆解 20% / 产品进化 10% / 成果对比 10%。

## 6. 剧本库（直接开拍）

### 模式1：正常刷题流（25–35 秒）

```
【0–3s】固定开场：「备考第XX天，开始今日刷题。」（字幕：第XX天·刷题XX道）
【3–20s】录屏快切做题界面，1.5–2 倍速，键盘鼠标原声
        口播：「今天练判断推理 20 道，中间两道定义判断卡了一下。」
【20–35s】结果页特写 + 足迹页
        口播：「正确率 XX%，错题已进复习。明天继续。一起打卡。」
```

### 模式2：错题复盘流（30–40 秒）

```
【0–3s】「备考第XX天，今天死磕一道错题。」
【3–25s】错题本界面 → 红叉特写 → 解析页（局部放大 200%）
        口播：「资料分析第三步栽在单位陷阱。考点已挂到知识框架，
        系统自动排了复习。」
【25–40s】知识框架树节点亮起的画面
        口播：「让错题长成一棵树，而不是堆成垃圾堆。」
```

### 模式3：专项突破流（35–45 秒）

```
【0–3s】「备考第XX天，专项突破资料分析。」
【3–30s】进专项 → 材料折叠展开 → 计时做题（快进）
        口播：「集中练增长量比较，用秒杀技巧，平均每题 50 秒以内。」
【30–45s】结果对比页
        口播：「正确率从 70% 提到 XX%。专项就要这样死磕。」
```

### 特别剧本（每周可选 1 条，制造记忆点）

| 剧本 | 一句话 | 亮点 |
|------|--------|------|
| **《与 AI 辩经》** | 「这道题我不同意 AI 的解析，我们来开个 issue。」→ 提交反馈 → 「人机对战，暂时 1:1」 | 程序员梗 + 保持质疑 |
| **《30 分钟刷题挑战》** | App 生成随机挑战任务（限时 15 分钟 10 题）→ 挑战成功音效 | 治好选择困难症，周末痛点共鸣 |
| **《开发者视角流》** | 左手敲代码右手刷题，"代码写累了，刷道题醒醒脑" | 双重努力人设拉满 |
| **《AI 判卷官上线》** | 手写申论拍照 → AI 批改结果逐条划重点 | 产品核心卖点（功能上线后启用） |
| **《时间流逝流》** | 延时摄影拍 30 分钟压缩成 10 秒，"虽然慢，但在路上" | 最省力，纯记录日兜底 |

## 7. 话术公式

### 7.1 三句话公式（不用背稿）

1. **进度**：「下班备考第 X 天，晚餐后 30 分钟做完一组真题。」
2. **收获**：「今天攻克两期比重计算，这个秒杀口诀直接选 A。」
3. **CTA**：「在职备考贵在坚持，我们终将上岸。」

### 7.2 单题讲解三步法（干货向）

**人类读题 → AI/解析 → 我的思考**。每期只讲 1–2 道题，不贪多：

- 做对难题版：「这道逻辑填空全网正确率 28%，我第一反应选 C……看了 AI 解析，逻辑线很清晰。拿下。」
- 做错反思版：「算到第三步栽在单位陷阱……AI 把我的步骤和标准步骤并列对比，红标了跳坑那一步。这个坑它只能指给你看，跳不跳靠自己。」

### 7.3 标题公式

**数字 + 痛点 + 悬念**：

- 「我用 AI 备考第 15 天，行测正确率涨了 12%」
- 「Bug 修到一半，刷 10 道题冷静下」
- 「打卡第 47 天｜正确率 78%，波动有点大」
- 「模考 55 分那天，我决定给自己写个刷题软件」

**黄金 3 秒钩子**（冲突/悬念开场）："今天模考只有 55 分，但我发现了一个规律……"

### 7.4 标签

必带：#公务员考试 #省考 #国考 #行测 #申论
人设：#程序员 #独立开发 #学习打卡 #上岸
系列：#30天公考打卡 #资料分析专项周 #申论开采日记 #模考复盘

## 8. 每日生产 SOP（学习+拍摄一体化，总附加成本 ≤10 分钟）

### 8.1 随手拍时间线（学习中顺手完成）

| 时点 | 动作 | 素材 |
|------|------|------|
| 第 0 分钟 | 架好手机（固定位），录 3 秒点击刷题画面 | 开场 |
| 第 15 分钟 | 顺手录 5 秒草稿纸划线/翻书 | 过程 |
| 第 30–60 分钟 | 刷完，录 3 秒结果页 + 在笔记本画勾 | 战报 |
| 平时 | 随手截图关键节点（正确率/足迹/思维导图） | 备用素材 |

### 8.2 剪辑五步（剪映，≤8 分钟，死规矩）

1. **粗剪**：只留"开始答题→成绩展示"，剪掉发呆和口误；
2. **倍速**：答题过程 1.5–2 倍速，口播正常速；
3. **聚焦**：展示解析细节时局部放大 200%；
4. **声音三轨**：BGM（10–20%）+ 原声（键盘鼠标音放大）+ 剪映文字转语音（开场白/要点）；
5. **套模板**：固定开头/结尾字幕/封面模板，只换数字。

> 剪映存三个模板：片头模板、封面模板、结尾字幕「知行公考｜读得进，练得出」（App 名定稿后替换）。

### 8.3 发布

- **时间**：固定晚 8–10 点（备考人群下班高峰），形成期待；
- **频率**：日更起步，稳定后 5–7 条/周；断更宁短勿缺——15 秒也要发；
- **平台**：视频号为主，小红书同步（备考女性用户多），B 站存程序员向长内容；
- **互动**：每条评论必回（初期权重关键）；自己置顶引导问题（"想看哪个模块的技巧？"）；
- **指标**：**看完播率，不盯播放量**——优化前 3 秒和字幕。

## 10. 选题弹药库（永远不缺灵感）

**日常向**：周末摆烂后如何强制启动 / 正确率波动大的焦虑 / 通勤静音刷题 / 加班到 9 点还学不学
**方法向**：截位直除法 / 错题本怎么用才不白记 / 人民日报开采流程 / 知识框架树怎么建
**产品向**：我为什么开发这个软件 / 给自习室加个"自律 buff" / 这个功能下周上线想内测的扣 1
**数据向**：刷题 1000 道发现的规律 / 各模块正确率月度曲线 / 模考前后对比
**心路向**：程序员裸辞/在职备考值得吗 / 分数出来那一刻 / 那些治好了我拖延症的功能

**独有选题源**：管理后台看用户正确率分布（v2 有用户后）→ 大家都弱的模块 = 下一期视频主题。

## 11. 心法（贴在显示器边上）

1. **连续性 > 完美**。粉丝追的不是你今天对了几道题，是"这个程序员居然真的坚持下来了"——养成系的期待感就是最大的流量密码。
2. 你不需要等软件完美。**"正在优化"这件事本身，就是最精彩的故事。**
3. 真实感 > 精美度。保留失误、叹气、涂改。
4. 每条视频必须有一个"可行动"的点——观众看完知道明天自己可以怎么练。
5. 场景永远是同一张桌子，角度永远是 45° 俯拍，时长永远 35 秒左右，开头永远说「备考第 XX 天」，内容永远只围绕「今天刷了什么 + 正确率 + 一句感受」。
