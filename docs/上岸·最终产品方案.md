# 上岸 · 公务员考试学习 + 社区产品 最终方案

> 版本：v2.0（综合稿）· 2026-08-02
> 本文档综合 `docs/` 下四份设计方案 + 初版 PRD 的全部优点，为最终执行依据。
> 上游项目：`zhengkao-tong`（知行）。

---

## 1. 定位

**一句话**：一个以"上岸"为唯一目标的公考个人成长操作系统——学 → 练 → 测 → 复 → 分享，所有学习行为自动沉淀为可分享的备考记录。

**是什么 / 不是什么**：


| ✅ 是                         | ❌ 不是                     |
| --------------------------- | ------------------------ |
| 公考个人成长 OS（计划→学习→练习→复盘→成长闭环） | 又一个题库 App（粉笔/华图/中公已卷到极致） |
| 沉浸式备考伴侣：打开就知道今天干什么          | 功能堆砌的个人管理系统（知行的老路）       |
| 未来是"公考学习朋友圈"（轻社区）           | 重论坛 / 陌生人社交              |


**差异化三件套**（市面产品没有的组合）：

1. **完整闭环**：阅读 → 框架 → 练习 → 复盘 → SRS 复习，不是题库堆砌；
2. **申论垂直深耕**：多数考生"会刷行测、不会申论"——人民日报三刀解剖 + 规范词 + 阶梯训练是独有资产；
3. **真实养成叙事**：开发者本人即第一用户，App 成长与备考过程全程公开（视频号），产品自带内容飞轮。

**功能取舍唯一标准**：是否直接服务笔试/面试提分，或服务"坚持学习"本身。

## 2. 三大使命与增长飞轮


| #   | 使命                        | 落地设计                     |
| --- | ------------------------- | ------------------------ |
| 1   | 自用备考：我是第一用户，每天用它学习，边备考边打磨 | 「今日」驾驶舱驱动日闭环；M2 起每天真实使用  |
| 2   | 视频号联动：学习记录做视频，自我督促 + 引流   | 上岸卡片自动生成，学完即出图、出图即素材     |
| 3   | 社区化铺垫：从单机工具演进为备考社区        | v1 预埋动态事件数据，社区是事件的"读取视图" |


```
飞轮：我备考 → 开发/打磨软件 → 每日学习数据 → 视频号内容
        ↑                                          ↓
   产品完善 ← 社区沉淀 ← 用户进入 App ← 内容引流
```

## 3. 用户与场景

- **v1 用户 = 我本人**（目标省考/国考）。按单用户自用设计，数据结构按多用户设计。
- **v2 用户**：视频号引流的备考同路人（在职/应届/多次参考，1 万量级社区规模假设）。

**日循环场景**：

```
早上：打开 App → 今日驾驶舱：倒计时 + 今日任务 + 到期复习 + AI 建议
白天：碎片刷题（练习 Tab）；整块时间：资料分析专项 / 申论精读 / 时政
晚上：今日复盘 → 自动出「上岸卡片」→ 发视频号
周末：真题套卷 → 能力雷达更新 → 周复盘 → 周报卡
```

**设计铁律：每天打开 App，30 秒内知道今天该干什么。**

## 4. 能力模型：按考试倒推功能（产品骨架）

### 4.1 行测五模块


| 模块   | 考察能力               | 占比（国考） | 现状          | 建设方式             |
| ---- | ------------------ | ------ | ----------- | ---------------- |
| 常识判断 | 政治/法律/经济/历史/科技知识运用 | ~13%   | ✅ 知识框架 + 时政 | 时政文章 + 考点树 + 刷题  |
| 言语理解 | 语境分析、主旨概括、词语辨析     | ~27%   | ⚠️ 语料本已有    | 专项题库（P1）         |
| 数量关系 | 数学运算、数字推理          | ~10%   | ❌           | 专项题库 + 公式速记（P1）  |
| 判断推理 | 图形/定义/类比/逻辑        | ~27%   | ❌           | 专项题库 + 错题归纳（P1）  |
| 资料分析 | 快读、公式运用、速算         | ~13%   | ✅ 最成熟（9 页）  | **模板模块**，复制到其余四科 |


### 4.2 申论五题型（差异化重点）


| 题型                        | 应用内形态                                        | 现状   |
| ------------------------- | -------------------------------------------- | ---- |
| 归纳概括 / 综合分析 / 提出对策 / 贯彻执行 | 题型训练：材料 + 作答 + 参考答案对照自评 + 评分维度（要点/逻辑/格式）     | ❌ P1 |
| 大作文                       | 人民日报三刀解剖 + 开采本 + 规范词库 + 阶梯训练（造句→仿写→口述）+ 骨架模板 | ✅ 已有 |


### 4.3 时事政治（贯穿行测常识 + 申论 + 面试）

时政文章阅读（分节进度/思维导图/读完出题）✅ + 事件复盘时间线 ✅ + 每日必读 ✅。

### 4.4 面试（P2，笔试后启动）

结构化面试四题型卡 + 口述录音自评 + 答题骨架。v1 只预留数据表。

### 4.5 每个模块的统一学习路径（六步法）

任何行测模块都走同一条路，保证体验一致、模块可复制：

```
知识体系 → 技巧学习 → 专项训练 → 真题训练 → 错题复盘 → 能力评估
（考点树）  （公式/技巧库）（drill）   （套卷）    （错题本+SRS）（雷达图）
```

每个模块页展示个人能力刻度：正确率、速度、薄弱题型 Top3、一键进入对应专项。

### 4.6 底层支撑（决定能否坚持）


| 能力   | 功能                                  |
| ---- | ----------------------------------- |
| 记忆保持 | SRS 复习中心（错题 + 知识点 + 规范词聚合）          |
| 节奏管理 | 今日清单 + 复盘 + 签到 + 倒计时 + 弹性模式（周末自动降量） |
| 元认知  | 双错题本（文章错题 + 手动录入拍照）+ 能力雷达图          |
| 激励   | 积分 + 排行 + 勋章 + 上岸卡片                 |

## 5. 产品结构

### 5.1 Tab 策略：4 Tab 起步，预留社区位


| Tab    | 定位    | 说明                          |
| ------ | ----- | --------------------------- |
| **今日** | 备考驾驶舱 | 打开即知今日所为（v1 第一 Tab）         |
| **学习** | 输入    | 时政 / 申论 / 资料分析 / 知识框架 / 语料本 |
| **练习** | 输出    | 刷题 / 专项 / 套卷 / 错题本 / 复习中心   |
| **我的** | 档案    | 数据 / 签到 / 积分 / 足迹 / 设置      |


> v2 社区上线时，TabBar 中间插入「社区」（5 Tab），今日页保留社区热帖预览卡。v1 的社区存在感靠：今日页动态预览 + 打卡卡片分享 + 排行榜。

### 5.2 功能地图

```
上岸 App
├── 今日（驾驶舱）
│   ├── 倒计时（目标考试 + 日期可配）+ 今日已学时长
│   ├── 今日任务清单（模板按星期配置；一键开始；完成度环）
│   ├── 到期复习提醒 → 复习中心
│   ├── AI 建议卡（v1.5 起）："今天建议先攻资料分析"
│   ├── 今日复盘（完成度/弱项/明日重点/心情）
│   ├── 昨日数据条（时长/正确率/连续天数）
│   ├── 上岸卡片入口（打卡卡/周报卡/里程碑卡/成绩卡）
│   └── 社区动态预览（v2）
├── 学习（输入）
│   ├── 时政阅读：详情（分节/目录/进度）+ 思维导图 + 读完刷题 + 每日必读
│   │   └── 强化：文章↔知识框架双向关联；重点段落一键采集进规范表达库
│   ├── 申论·人民日报：时评精读（三刀解剖）+ 开采本 + 规范词库（学习/掌握/进复习）+ 阶梯训练
│   ├── 行测学习地图：五模块入口，各含 知识体系→技巧→专项→真题→错题→评估
│   │   └── 资料分析：公式库（KaTeX）+ 题型库 + 秒杀技巧 + 薄弱题型统计
│   ├── 知识框架：多棵考点树（行测各科 + 申论要素 + 时政热点）+ 笔记/星标/掌握度 + Obsidian md 同步
│   └── 语料本：选中采集 + 标签 + 知识点挂载 + 沉淀规范词
├── 练习（输出）
│   ├── 刷题：今日精选（按薄弱点推荐）/ 随机 / 按模块 / 按知识点 / 按文章 / 错题重练
│   │   └── 每题：收藏 / 加笔记 / 一键进错题本 / 解析看不懂→AI 讲解（v1.5）
│   ├── 专项 drill：资料分析已有 → 复制到言语/数量/判断（材料折叠+计时+逐题+结果解析）
│   ├── 真题套卷：限时 → 交卷 → 成绩报告（分模块得分/用时/正确率趋势/复习建议）
│   ├── 错题本：文章错题 + 行测手动错题（拍照/OCR/考点关联/掌握标记/可生成打印）
│   │   └── 错题 ↔ 知识框架节点双向跳转
│   └── 复习中心：SRS 聚合（错题/知识点/规范词到期任务）
├── 我的
│   ├── 备考档案：备考天数/累计小时/刷题数/能力雷达图（行测五模块+申论）
│   ├── 签到日历 + 积分流水 + 排行榜（日/周/月/总）
│   ├── 上岸足迹：里程碑（首套卷/千题/连续30天/正确率新高）
│   ├── 收藏（题目/文章/帖子）+ 消息中心（v2）
│   ├── 个人资料 / 反馈 / 深色模式
│   └── 会员中心（v3，暂为占位）
└── 社区（v2 独立 Tab，详见 §8）
```

页面规模：P0 约 52 页（知行迁移 46 页改造 + 新建约 6 页），v2 社区再加 8–10 页。

## 6. 重点页面设计

### 6.1 今日驾驶舱（新增核心页）

```
┌─────────────────────────────┐
│ [头像] 距离2027省考 128天      │
│ 今日已完成 ██████░░ 70%        │
├─────────────────────────────┤
│ 今日任务                      │
│ □ 资料分析 20题   [一键开始]   │
│ □ 人民日报精读 1篇             │
│ □ 错题复盘 15分钟              │
│ ＋ 临时任务                    │
├─────────────────────────────┤
│ 到期复习 12 项 → [去复习]      │
├─────────────────────────────┤
│ 昨日：2h20m · 正确率76% · 连续15天 │
├─────────────────────────────┤
│ [生成今日上岸卡片]             │
└─────────────────────────────┘
```

### 6.2 答题流（继承知行，强化）

答题页极简（题干+选项+底部导航，无干扰）→ 即时对错与解析 → 结果页强反馈（正确率 + 排名 + 积分动效）→ 错题自动关联知识点并进 SRS。

### 6.3 申论训练页（差异化）

材料 → 作答（文本/拍照）→ 对照参考答案 → 按维度自评（要点齐全度/逻辑层次/规范表达/格式）→ 记录得分进雷达图。AI 批改版（OCR + LLM 打分）为 v1.5 升级位。

## 7. AI 能力路线（分层，不画饼）

v1 的"智能"全部用**规则实现**（不依赖 LLM，稳定可用）；LLM 功能后置且可开关（现有 `llm_enabled` 机制继承）。


| 能力              | 实现                          | 版本   |
| --------------- | --------------------------- | ---- |
| 今日精选组题          | 规则：按错题本 + 各模块正确率抽题          | v1   |
| 薄弱项诊断           | 规则：分模块/题型正确率统计 → 雷达图 + 建议文案 | v1   |
| 智能组卷            | 规则：指定弱项模块自动抽题成卷             | v1.5 |
| AI 解析（题目看不懂）    | LLM，默认关闭                    | v1.5 |
| AI 申论批改（OCR+评分） | LLM，默认关闭                    | v1.5 |
| AI 学习规划（目标→周计划） | LLM                         | v2   |
| 拍照笔记转知识点        | OCR + LLM                   | v2   |


> 管理后台预留：Prompt 管理、模型配置、LLM 开关（沿用知行 SystemSetting）。

## 8. 社区化三阶段（v1 预埋，不提前做 UI）

**核心架构**：所有学习行为从 v1 起写入 `activity_event`（event-sourcing），社区 = 事件的读取视图。v2 做社区时零补采数据。

```
activity_event: id, user_id, type, payload_json, is_public, created_at
type: sign_in | quiz_done | exam_done | drill_done | article_read
    | shenlun_mined | streak_milestone | card_generated | post_published(v2)
```


| 阶段  | 版本  | 内容                                                                                                    |
| --- | --- | ----------------------------------------------------------------------------------------------------- |
| 预埋  | v1  | activity_event 表 + 个人足迹页 + 排行榜 + 打卡卡片（可分享图片）                                                          |
| 轻社区 | v2  | 动态广场（图文/打卡/笔记/经验，话题标签）· 点赞/评论/收藏/关注 · 学习小组（组队打卡、组内排行、组长督学）· 题目问答区（拍照求助）· 精选/置顶机制 · 消息中心 · 社区积分与学习积分打通 |
| 社区  | v3  | 按考试分圈（2027国考/江苏省考…）· 上岸故事 · 资料共享（审核后发布）· 互批申论（人工审核）                                                   |


**社区红线**：

- 成绩/错题**默认私密**，公开必须显式开关（备考人群对分数敏感）；
- 不做匿名、不做陌生人私聊（合规 + 维护成本）；
- 内容审核后台（审核/敏感词/禁言/举报处理）与社区 UI **同版本上线**，不滞后；
- 不做重论坛，信息流卡片式，轻互动优先。

## 9. 上岸卡片 + 视频号运营（内容飞轮）

### 9.1 上岸卡片生成器（P1 核心）

Taro Canvas 绘制 → 存相册。走设计系统变量，留固定"视频号水印位"。


| 卡片       | 触发      | 内容                            |
| -------- | ------- | ----------------------------- |
| 今日打卡卡    | 复盘完成/手动 | 日期、倒计时、学习时长、题数、正确率、连续天数、一句自勉  |
| 周报卡      | 每周复盘    | 本周投入、模块分布、正确率变化曲线、下周目标        |
| 里程碑卡     | 自动      | 首套卷 / 累计1000题 / 连续30天 / 正确率新高 |
| 成绩卡      | 套卷交卷    | 总分、分模块得分率、用时分布                |
| 开采卡（社区用） | 申论开采完成  | 今日论点/规范词摘录（v2 分享到社区）          |


**要求：卡片必须"值得发"——这是视频号素材的供给端。**

### 9.2 视频号定位

- **账号名**：如"程序员考公日记"/"上岸日记"（一眼看懂，与 App 名联动）；
- **人设**："死磕公考的程序员"——全栈开发者 + 真实备考人，养成系剧本，不卖课不割韭菜；
- **风格**：极简桌面记录风，屏幕录制 + 口播/字幕为主，可不露脸；真实感 > 精美度；
- **平台**：视频号为主（用户明确要求），小红书同步分发（备考女性用户多），B 站存程序员向内容；
- **变现**：现阶段不考虑，只做自我督促 + 引流（明确共识）。

### 9.3 内容支柱（每周配比）


| 支柱     | 占比  | 示例                        |
| ------ | --- | ------------------------- |
| 每日学习记录 | 60% | "Day 30：资料分析错了一半，心态崩了又重建" |
| 方法拆解   | 20% | "资料分析秒杀技巧：这个公式我写进了代码"     |
| 产品进化   | 10% | "因为市面刷题软件不好用，我决定自己写一个"    |
| 成果对比   | 10% | "刷题正确率 55%→72% 的那一周"      |


### 9.4 每日生产流程（30–60 分钟，可坚持）

1. 固定时段真实学习（用 App），过程中随手截图关键节点（刷题界面/正确率/开采本/足迹页）；
2. 手机录 1–3 分钟口播或屏录（讲解思路即可）；
3. 剪映套**固定模板**（片头/字幕样式/BGM 已存）：粗剪 → 1.2–1.5 倍速 → 自动字幕 → BGM 10% → 封面大字标题；
4. 晚 8–10 点发布（备考人群高峰）；日更起步，稳定后 5–7 条/周。

### 9.5 脚本与标题公式

- **黄金 3 秒钩子**：冲突/悬念开场——"今天模考只有 55 分，但我发现了一个规律…"；
- 中段：过程/干货（代码→界面→数据快切）；
- 结尾：行动号召——"关注我，看我能不能一次上岸"；
- **标题公式**：数字 + 痛点 + 悬念——"我用 AI 备考第 15 天，行测正确率涨了 12%"；
- 系列化标签：#30天公考打卡 #资料分析专项周 #申论开采日记 #模考复盘；
- **核心指标看完播率**（> 播放量），优化前 3 秒与字幕；每条评论必回。

### 9.6 产品反哺内容（独有优势）

管理后台看**用户正确率分布**（v2 有用户后）→ 发现大家都弱于某模块 → 针对性出一期技巧视频。内容选题永远来自真实学习数据，不缺灵感。

## 11. 技术架构与迁移

### 11.1 技术栈（完全复用知行，零学习成本）

```
移动端：Taro 4 + Vue 3 + NutUI + Sass（微信小程序优先 + H5）
后端：FastAPI + SQLite（量起来再迁 PostgreSQL）；uploads/ 独立目录
管理端：Vue 3 + Element Plus（admin-web 两级菜单直接复用）
部署：Docker Compose，整包 data 备份（沿用 deploy-ali.md）
```

### 11.2 工程策略：复制改造，不做代码级共享

新仓库从知行复制 `src/` + `server/`，按下表删改。两应用生命周期不同（知行冻结、新应用高频迭代），共享包互相牵制。

### 11.3 迁移映射

**迁移（P0）**：auth · article · question(8页) · exam(4页) · ziliao(9页) · knowledge · review · rmrb(7页) · corpus · plan(4页) · events · user(profile/signin/points/rank/growth/feedback) · index(重构为今日+学习)

**砍掉**：english(16) · dushu(7) · health(7) · ledger(6) · wealth(7) · user/recharge；对应后端 API 域、数据表、后台菜单一并不带。

**后端保留域**：认证/用户/文章刷题/学习记录/签到积分/复习/计划/知识/行测错题/套卷/资料分析/申论RMRB/语料本/事件复盘/足迹 + **新增**：activity_event、卡片数据聚合、雷达图、倒计时配置、(v2)社区域。

**横切能力全继承**：JWT+RBAC · 积分 · 深色主题（CSS 变量）· SRS 记忆曲线 · 语音输入 · KaTeX · platform.ts 反馈封装 · formFlush。

**数据迁移**：本人公考数据（文章/题目/错题/开采/知识点）导出导入；英语读书等留知行。

## 12. 视觉与交互原则

- **基调**：沉稳专注。大留白 + 卡片式（轻阴影大圆角）+ 清晰层级；深色模式完整支持；
- **主色**：待定（§14）——延续品牌红 or 换深蓝/墨绿"理性学习"色系以区隔培训机构的红黄风；
- **首页**：Banner 低矮，任务卡突出，主线入口图标网格 2–3 列；
- **答题页极简，结果页强反馈**；列表上拉分页 + 骨架屏；社区流虚拟列表（性能）；
- **激励微动效**：完成任务轻量反馈（打卡成功震动/积分动画），游戏化克制使用；
- **交互统一**（继承知行规范）：全局反馈走 platform.ts；表单保存前 flush 语音输入；导航封装；px 单位；scoped style；颜色走变量不硬编码。
