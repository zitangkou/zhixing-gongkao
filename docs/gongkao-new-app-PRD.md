## 0. 一句话定位

**一个以"上岸"为唯一目标的每日学习闭环应用：学 → 练 → 纠 → 记，所有学习行为自动沉淀为可分享的备考记录。**

不做"学习平台"，做"上岸工具"。功能取舍唯一标准：**这个功能是否直接服务于笔试/面试分数提升，或服务于坚持学习本身。**

---

## 1. 为什么要做新应用

### 1.1 现状问题

知行目前 98 个页面、约 17 个功能域，其中与公考无关的占一半：

| 类别 | 页面数 | 说明 |
|------|--------|------|
| 公考主线 + 学习闭环 | ~46 页 | article / question / exam / ziliao / knowledge / review / rmrb / corpus / plan / events / 部分 user |
| 与公考无关 | ~43 页 | english(16) / dushu(7) / health(7) / ledger(6) / wealth(7) |
| 账号基础 | ~9 页 | auth + user 其余 |

功能过多导致：定位模糊、首页入口拥挤、开发精力分散、新用户（未来社区用户）上手成本高。

### 1.2 新应用的三个使命

| # | 使命 | 对应设计 |
|---|------|----------|
| 1 | **自用备考**：我是第一个用户，每天基于它学习、自我提升，同时持续打磨应用 | 「今日」驱动的日闭环；所有功能自己先用 |
| 2 | **视频号联动**：每天把学习记录做成视频，自我督促 + 引流，探索第二收入（暂不考虑变现） | 内置「上岸卡片」生成器，学习结果一键出图，App 和视频号互为飞轮 |
| 3 | **社区化铺垫**：未来从单机工具演进为备考社区 | 数据模型从 v1 预埋动态/可见性字段，社区只是已有学习事件的"读取视图" |

## 2. 用户与场景

### 2.1 目标用户

- **v1 用户 = 我本人**（在职/全职备考，目标省考/国考）。产品按单用户自用设计，但数据结构按多用户设计（账号体系已有）。
- **v2 用户**：视频号引流来的备考同路人（1 万人以内的社区规模假设）。

### 2.2 核心场景（日循环）

```
早上：打开 App →「今日」看到倒计时 + 今日任务清单 + 到期复习
白天：碎片时间刷题（练习 Tab）；整块时间学资料分析/申论/读时政
晚上：完成今日复盘 → 生成「上岸卡片」→ 发视频号/朋友圈
周末：做一套真题卷 → 能力雷达图更新 → 周复盘
```

**设计原则：每天打开 App 30 秒内知道"今天该干什么"。**

## 3. 公务员考试能力模型（功能设计的骨架）

新应用的功能不按"我想做什么"堆砌，而是按**考试实际考察什么**倒推。

### 3.1 行测（行政职业能力测验）

| 模块 | 考察能力 | 题量占比（国考参考） | 应用内对应功能 | 现状 |
|------|----------|----------------------|----------------|------|
| 常识判断 | 政治理论、法律、经济、历史、科技、地理的知识储备与运用 | ~13% | 知识框架（考点树）+ 时政文章 + 刷题 | ✅ 已有（knowledge + article） |
| 言语理解与表达 | 语境分析、主旨概括、细节判断、词语辨析 | ~27% | 言语专项题库 + 语料本（词语/表达积累） | ⚠️ 题库待建（corpus 已有） |
| 数量关系 | 数学运算、数字推理 | ~10% | 数量专项题库 + 公式速记 | ❌ 待建（P1） |
| 判断推理 | 图形推理、定义判断、类比推理、逻辑判断 | ~27% | 判断专项题库 + 错题归纳 | ❌ 待建（P1） |
| 资料分析 | 快速读数、公式运用、速算技巧 | ~13% | 公式库 + 题型库 + 秒杀技巧 + 专项练习 | ✅ 最成熟（ziliao 9 页，作为其他模块的模板） |

### 3.2 申论

| 能力 | 考察形式 | 应用内对应功能 | 现状 |
|------|----------|----------------|------|
| 归纳概括 | 概括问题/原因/做法 | 题型训练（对答案自评） | ❌ 待建（P1） |
| 综合分析 | 谈理解/谈启示 | 题型训练 | ❌ 待建（P1） |
| 提出对策 | 针对性、可行性 | 题型训练 | ❌ 待建（P1） |
| 贯彻执行 | 公文/应用文写作 | 题型训练 + 格式模板库 | ❌ 待建（P1） |
| 大作文 | 议论文 | 人民日报三刀解剖 + 规范词 + 阶梯训练 + 骨架模板 | ✅ 已有（rmrb，素材与语感训练） |

> 申论批改 v1 采用"参考答案对照自评"模式（AI 批改依赖 LLM，默认关闭，列为 P2）。

### 3.3 时事政治（贯穿行测常识 + 申论 + 面试）

- 时政文章阅读（分节进度 + 思维导图 + 读后出题）✅ 已有
- 事件复盘（时间线 + 关联知识框架）✅ 已有
- 每日必读推荐 ✅ 已有

### 3.4 面试（结构化）

笔试通过后才需要，列为 **P2**。形态预告：题目卡（综合分析/组织计划/应急应变/人际）+ 口述录音自评 + 答题骨架模板。v1 只做数据表预留，不做页面。

### 3.5 底层支撑能力（不对应考试科目，但决定能否坚持）

| 能力 | 功能 |
|------|------|
| 记忆保持 | SRS 间隔重复复习中心（错题 + 知识点 + 规范词） |
| 节奏管理 | 学习计划（今日清单 / 复盘）+ 签到 + 倒计时 |
| 元认知 | 错题本（文章错题 + 手动录入）+ 能力雷达图 |
| 坚持激励 | 积分 + 排行 + 上岸卡片（可视化成果） |

## 4. 产品结构

### 4.1 底部 Tab（4 个）

| Tab | 页面 | 定位 |
|-----|------|------|
| **今日** | `pages/today/index` | 日驱动中枢：倒计时、今日清单、到期复习、打卡、今日数据、上岸卡片入口 |
| **学习** | `pages/learn/index` | 内容输入：时政阅读、申论·人民日报、资料分析知识库、知识框架、语料本 |
| **练习** | `pages/practice/index` | 输出训练：刷题模式、专项练习、真题套卷、错题本 |
| **我的** | `pages/mine/index` | 账号、签到、积分、排行、能力雷达图、足迹、设置 |

> 与知行的差异：新增「今日」为第一 Tab（日闭环驱动），把"学习"（输入）与"练习"（输出）拆开，心智更清晰。

### 4.2 功能地图

```
上岸 App
├── 今日（日闭环）
│   ├── 考试倒计时（目标考试 + 日期可配）
│   ├── 今日任务清单（模板按星期配置，可临时增删）
│   ├── 到期复习提醒 → 复习中心
│   ├── 今日复盘（完成度 / 弱项 / 明日重点）
│   └── 上岸卡片：今日打卡卡（学习分钟/题数/正确率/连续天数/倒计时）
├── 学习（输入）
│   ├── 时政阅读：文章详情（分节/目录/进度）+ 思维导图 + 读完刷题 + 每日必读
│   ├── 申论·人民日报：时评列表/详情 + 三刀解剖 + 开采本 + 规范词库 + 阶梯训练
│   ├── 资料分析：公式库 + 题型库 + 秒杀技巧 + 专项练习
│   ├── 知识框架：考点树（备注/标重点/掌握度）+ 知识点复习
│   └── 语料本：采集（选中文字）+ 标签 + 知识点挂载 + 沉淀规范词
├── 练习（输出）
│   ├── 刷题：今日精选 / 随机 / 时间线 / 重点突破 / 按文章练 / 错题重练
│   ├── 专项练习：资料分析（已有）→ 言语/数量/判断（P1，复用 ziliao drill 模式）
│   ├── 真题套卷：限时作答 → 交卷 → 成绩解析 → 历史 attempt
│   ├── 错题本：文章错题 + 行测手动错题（拍照/考点关联/掌握标记）
│   └── 复习中心：SRS 聚合（错题/知识点/规范词到期任务）
├── 我的
│   ├── 签到日历 + 积分明细 + 排行榜（日/周/月/总）
│   ├── 能力雷达图：行测五模块 + 申论，按正确率/训练量绘制
│   ├── 上岸足迹：累计数据 + 里程碑（首套卷/千题/连续 30 天…）
│   ├── 个人资料 / 反馈 / 深色模式
│   └── 社区入口（v2 开放）
└── 管理后台（admin-web 提取重建）
    ├── 内容运营：文章管理、分类管理
    ├── 题库建设：题库管理、试卷管理、错题审核
    ├── 资料库：资料分析资源、知识框架同步、人民日报资源、规范词
    ├── 学习运营：学习计划模板、推荐位配置
    ├── 社区运营（v2）：动态审核、举报处理
    └── 系统：用户管理、系统设置、角色权限
```

### 4.3 页面规模预估

P0 约 **52 页**（知行 46 页迁移改造 + 今日/卡片/雷达图等 ~6 页新建），比知行少近一半。

## 6. 社区化路线（为未来准备，不提前做 UI）

**核心设计：所有学习行为从 v1 起就记录为"动态事件"（event-sourcing 思路），社区 = 对这些事件的读取视图。这样 v2 做社区时零补采数据。**

### 6.1 动态事件模型（v1 预埋）

```
activity_event:
  id, user_id, type, payload_json, is_public, created_at

type 枚举（v1）：
  sign_in          签到
  quiz_done        完成一次刷题（题数/正确率）
  exam_done        完成套卷（分数）
  drill_done       专项练习（ziliao 等）
  article_read     读完时政文章
  shenlun_mined    申论开采（今日开采）
  streak_milestone 连续天数里程碑
  card_generated   生成上岸卡片
```

v1 只写不读（仅用于自己的足迹页和卡片数据源）；v2 加 `is_public` 开关与动态流。

### 6.2 三阶段路线

| 阶段 | 版本 | 内容 |
|------|------|------|
| 预埋 | v1 | activity_event 表 + 个人足迹页 + 排行榜（已有） |
| 轻社区 | v2 | 动态流（看别人打卡/成绩，可点赞）、学习小组（组队打卡）、可见性设置 |
| 社区 | v3 | 话题圈（按省考/国考/模块）、经验帖、题目讨论、举报审核后台 |

### 6.3 社区红线

- 成绩/错题默认私密，公开必须显式开关（备考人群对分数敏感）。
- 不做匿名、不做陌生人私聊（合规与维护成本）。
- 内容审核后台与社区 UI 同版本上线，不滞后。

## 7. 视频号联动设计

**目标：让"晒学习"成为零成本动作——学完即出图，出图即素材。**

### 7.1 上岸卡片（P1 核心功能）

| 卡片类型 | 触发 | 内容 |
|----------|------|------|
| 今日打卡卡 | 今日复盘完成 / 手动生成 | 日期、倒计时、学习分钟、题数、正确率、连续天数、一句自勉 |
| 周报卡 | 每周复盘 | 本周投入、模块分布、正确率变化曲线、下周目标 |
| 里程碑卡 | 自动触发 | 首套卷完成 / 累计 1000 题 / 连续 30 天 / 正确率新高 |
| 成绩卡 | 套卷交卷 | 分数、各模块得分率、用时分布 |

实现：Taro Canvas 绘制 → 保存相册。模板走设计系统变量，品牌一致；卡片留固定"视频号位"（账号名水印）。

### 7.2 内容素材闭环

App 内学习 → 卡片/数据截图 → 视频号视频 → 引流回 App → 社区（v2）。v1 不做 App 内视频能力，只做"出图"。

## 8. 技术架构

**完全复用知行技术栈，降低开发与维护成本：**

```
移动端：Taro 4 + Vue 3 + NutUI + Sass（H5 / 微信小程序）
后端：FastAPI + SQLite（Docker 卷：db + uploads + knowledge）
管理端：Vue 3 + Element Plus（admin-web，两级菜单）
部署：Docker Compose，整包 data 备份（复用 deploy-ali.md 流程）
```

**工程策略：复制改造，不做代码级共享。**

- 新仓库从知行复制 `src/` + `server/`，删除 §5.2 清单，改造入口与信息架构。
- 理由：两应用生命周期不同（知行可能冻结，新应用高频迭代），共享包会互相牵制；重复的横切代码量可控。
- 迁移顺序：先横切层（鉴权/主题/反馈/SRS/积分）→ 再页面模块按 P0 顺序 → 最后管理端。

**数据迁移**：我本人的公考相关数据（文章、题目、错题、开采记录、知识点）从知行 SQLite 导出导入新应用；英语/读书等数据留在知行。
