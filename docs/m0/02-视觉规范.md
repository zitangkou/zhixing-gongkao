# 02 · 视觉规范

> 应用：知行公考（zhixing-gongkao）
> 主色：深蓝 + 墨绿（与培训机构红黄区隔，强调理性学习）
> 适用：学员端 Taro 应用（H5 / 微信小程序）；管理后台沿用 Element Plus 默认
> 验收：前端动工前唯一视觉依据

---

## 1. 设计基调

| 维度 | 决策 | 说明 |
| --- | --- | --- |
| 调性 | **沉稳专注** | 与培训机构的"热闹推销"形成区隔 |
| 留白 | **大留白** | 信息密度低、决策成本低 |
| 形态 | **卡片式** | 轻阴影 + 大圆角（12-16px）+ 清晰层级 |
| 暗色 | **完整支持** | 所有色值有暗色对应 |
| 动效 | **克制** | 完成轻量反馈（积分动画、打卡震动），不堆特效 |
| 字体 | **系统字体栈** | iOS SF / Android Roboto / 微信小程序默认 |
| 单位 | **px** | 与知行保持一致，不引入 rem/rpx |

## 5. 上岸卡片视觉规范（M4 关键交付）

### 5.1 设计原则

1. **必须"值得发"**：每张卡片都是视频号素材的供给端
2. **统一画布**：所有卡片 750×1334px（3:4，方便视频号/小红书竖屏）
3. **品牌强识别**：左上 Logo + 右上"知行公考"文字 + 右下"扫码下载"位
4. **留视频号水印位**：右下角固定 120×120px 区域，画布上明确预留
5. **数据高对比**：核心数据（连续天数、正确率、题数）用 Display 字号 + 主色

### 5.4 渲染与导出

- **技术栈**：Taro Canvas 2D（与小程序原生 Canvas 一致）
- **统一入口**：`src/utils/cardRenderer.ts`
  - `renderCard(type, data): Promise<string>` 返回图片本地路径
  - `saveToAlbum(path): Promise<void>` 保存到相册
  - `share(path): Promise<void>` 调起分享面板
- **导出尺寸**：750×1334px（3:4），DPR 2x
- **导出格式**：PNG（默认）/ JPEG（体积敏感时）
- **失败处理**：Canvas 渲染失败 → 兜底用 SVG 拼装 → 再失败提示用户手动截图

## 8. 交互微动效

### 8.1 全局规范

| 场景 | 动效 | 时长 | 缓动 |
| --- | --- | --- | --- |
| 页面进入 | 从下往上滑入 | 200ms | ease-out |
| 页面退出 | 向上滑出 | 150ms | ease-in |
| 弹层出现 | 缩放 0.95 → 1.0 + 淡入 | 200ms | ease-out |
| Tab 切换 | 渐变 | 150ms | ease |
| 按钮点击 | 缩放 0.96 + 背景变深 | 100ms | ease |
| 列表项点击 | 背景临时变 `--color-gray-50` | 100ms | ease |
| 打卡成功 | 轻震动 + 琥珀色淡出圈 | 600ms | ease-out |

### 8.2 积分动效（克制使用）

- 完成刷题 / 签到 / 开采：右上角小徽章 "+10" 从下浮入 600ms 后淡出
- 不做金币雨、粒子特效等重动效

### 8.3 骨架屏

- 颜色：`--color-gray-100`，透明度 50% ↔ 100% 渐变
- 周期：1500ms
- 形状：与最终内容大致一致（圆角矩形）

## 9. 响应式与适配

### 9.1 屏幕尺寸

- **H5**：适配 320px - 768px 宽度
- **微信小程序**：以 iPhone 6 (375×667) 为基准设计稿

- iPhone X+ 底部安全区：34px（用 `env(safe-area-inset-bottom)`）

- **仅竖屏**：v1 不做横屏适配
- 全局 CSS：`@media (orientation: landscape) { /* 提示用户旋转 */ }`
