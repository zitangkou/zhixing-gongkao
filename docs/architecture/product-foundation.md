# 多题型产品共享底座技术设计

> 版本：1.0 · 2026-08-23

## 1. 目标

首期承载`shenlun`和`theory`，以后通过题型插件接入`ziliao`、`quantity`、`verbal`、`judgement`。采用模块化单体、一套后端、多小程序入口；不复制账号、题目、审核、SRS和运营系统。

## 2. 分层

- 产品层：品牌、首页、Tab、功能开关、AppID和发布状态。
- 通用学习层：任务、内容资产、作答会话、进度、收藏、错题、SRS和指标。
- 题型插件层：展示、交互、评价、错因、复习生成、能力指标和运营模板。
- 内容运营层：来源、版本、教研/运营审核、内容包、平台变体、日历和归因。

## 3. 产品上下文

- 客户端构建常量`PRODUCT_KEY`，请求统一发送`X-Product-Key`。
- 服务端验证产品键并解析配置；未知产品返回400。
- `general`为现有综合版兼容值，`shenlun`和`theory`为首发产品。
- 产品上下文必须从服务端依赖获取，不允许业务自行读取未校验Header。
- Sprint 0先建立上下文和配置；后续数据模型逐表加入`product_key`或发布关系，并补串台测试。

## 4. 首期配置

| key | 首页模式 | 模块 |
|---|---|---|
| general | dashboard | 现有全部模块 |
| shenlun | daily_training | 今日、学习、练习、我的 |
| theory | daily_pack | 今日、专题、刷题、我的 |

配置接口返回产品名、短名、主题、首页模式、Tab、启用模块和默认学习时长。

## 5. 兼容策略

- 未发送Header时使用`DEFAULT_PRODUCT_KEY=general`，现有客户端行为不变。
- 现有表和API暂不强制迁移；新增垂直数据从第一天携带产品键。
- 现有`rmrb`和文章/题目接口逐步加产品发布范围，不一次性重写。
- SQLite继续使用`create_all + db_compat`，新表按域添加并提供幂等兼容补列。

## 6. 安全与测试

- Header白名单验证。
- 配置端点分别验证三个产品及默认回退。
- 前端普通请求、上传请求都发送产品键。
- 后续每个资源增加“同产品可见、跨产品不可见、共享发布可见”测试。
- 行为事件必须保存产品键，渠道归因同时保存`channel/content_id/campaign`。

## 7. Sprint 0交付

- 后端产品注册表、上下文依赖、公开配置响应。
- 配置项`DEFAULT_PRODUCT_KEY`和`ENABLED_PRODUCT_KEYS`。
- 前端`TARO_APP_PRODUCT_KEY`构建常量、请求/上传Header。
- 三产品配置测试和未知产品测试。
- 下一批：产品配置Store、双壳首页、任务状态机和数据隔离模型。
