## 1. 固定执行规程

每个开发单元严格按以下顺序推进：

1. 明确本单元目标、边界和验收条件。
2. 实施代码及必要文档修改，不混入其他未完成工作。
3. 完成自动化测试、静态检查和 H5／小程序构建等相应验证。
4. 在本文追加实施结果、实际能力、限制、验证证据和下一项。
5. 创建独立 Git 提交并推送到已确认远端。
6. 推送成功后自动进入下一项；遇到发布、密钥、外部发送或其他需要新增授权的动作时暂停确认。

“完成”只表示归档中列出的验收已通过，不代表已经部署、提审或公开运营。规划功能、代码功能、部署状态和平台发布状态分别记录。

## 2. 开发单元归档

### U01：时政文章免费学习闭环

- 状态：本地开发与验证完成；已创建提交，GitHub 推送待明确授权。
- 完成日期：2026-09-07。
- 本地提交：`0a4ffaa feat(theory): add guest article learning flow`。
- 产品范围：知行日知 H5、微信小程序、共用 FastAPI 后端。

#### 实际交付

- 未登录用户可以免费打开时政文章，选择“阅读全文”或“读重点”。
- 同一文章的已审核题目按每辑最多 5 题分组；题库完整时可以选择全文题目合集。
- 分辑与合集引用相同题目 ID，避免重复创建题目和错题身份。
- 单选、判断题点击后提交；多选题明确提交后才判定。
- 题面接口不返回答案、解析和原文依据；提交单题后才返回对应反馈。
- 游客作答及多选草稿按内容版本保存在当前设备；切换分辑、退出再进可以恢复。
- 内容版本变化后，旧页面停止继续判题并提示重新打开，避免新旧答案混判。
- 下线文章、未开放练习、待审核题和不完整题目不会进入公开合集。
- 今日页和复习页向游客提供文章学习入口，不再强制首次访问登录。
- 对外界面统一使用“时政学习”，产品名保持“知行日知”，主题配置统一为红色。

#### 数据与接口

- `GET /api/learning/articles/{article_id}`：返回已发布文章、无答案题面、分辑和内容版本。
- `POST /api/learning/articles/{article_id}/check`：校验内容版本、题目归属和选项后返回单题反馈。
- 两接口只允许 `X-Product-Key: theory`，不写账号积分、错题或阅读计数。
- 本地游客存储键包含文章 ID 和内容版本；当前尚未实现登录后的跨端合并。

#### 验证证据

- 后端相关测试：17 项通过，包括匿名分辑、答案隐藏、非法答案、跨产品隔离、内容下线和版本冲突。
- TypeScript：`tsc --noEmit -p apps/theory-app/tsconfig.json` 通过。
- ESLint：本单元相关页面、组件与 API 文件无错误。
- H5：`apps/theory-app` 的 `npm run build:h5` 通过。
- 微信小程序：`apps/theory-app` 的 `npm run build:weapp` 通过。
- 构建存在 Sass `@import` 和 legacy JS API 的上游弃用提示，不影响本次产物生成，后续作为工程升级事项处理。

#### 明确限制

- 游客记录目前只在本机保存，清理浏览器／小程序缓存会丢失；还不能登录后合并到账号。
- “读重点”暂使用文章已审核摘要，还没有独立的段落级重点标注结构。
- 当前分辑按稳定题目顺序每 5 题切分；运营后台还不能人工调整分辑、固定发布版本或标记长期重点专题。
- 尚未生成公众号、小红书、知乎、视频号的正式入口和运营发布包。
- 尚未部署、提审或公开发布。
