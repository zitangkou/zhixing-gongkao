### 1.3 答案文件期望格式

从 2025 的 `answers_*.json` 推断，中间文件格式为：

```json
[
  {
    "number": 1,
    "answer": "B",
    "explanation": "解析全文……",
    "subtype": "削弱",
    "anchor_stem": "题干前 40 字，用于锚点校验"
  }
]
```

- `number`：题号（int），与 paper 中 `questions[].number` 对应
- `answer`：单选 `"A"`，多选 `"ABD"`（升序无分隔），判断 `"正确"/"错误"`
- `explanation`：解析全文（可为空字符串）
- `subtype`：细题型（可为 null）
- `anchor_stem`：题干引用片段，用于锚点校验（可为空字符串）

merge_answers.py 同时兼容 `{"questions": [...]}` 包装格式。

## 2. 锚点校验流程说明

### 2.1 流程

```
answers_*.json (中间文件)
    │
    ▼
按 number 索引 paper 中的题目
    │
    ▼
① 答案格式校验（validate_answer）
   ├─ 单选：字母 ∈ options 键
   ├─ 多选：≥2 字母且升序，均 ∈ options 键
   ├─ 判断：∈ {正确, 错误}
   └─ 图形题（options=None）：接受 A-D 任意组合
    │
    ▼
② 锚点校验（anchor_match）
   策略1：题干前 N 字（归一化）是否出现在 anchor_stem+explanation 中
          N 逐级放宽：20 → 15 → 12 → 8
   策略2：题干前 20 字与 explanation 滑动窗口字符相似度 ≥ 0.35
   策略3：题干前 4 个 2-gram 中 ≥ 40% 出现在 explanation 中
    │
    ├─ 匹配成功 → 直接写入
    └─ 匹配失败 → 仍写入（题号映射可信），但加 anchor_pending flag，进 pending_review 清单
    │
    ▼
③ 写入字段：answer / explanation / answer_source / subtype
   清除 answer_missing flag，锚点失败则加 anchor_pending flag
    │
    ▼
④ 非 dry-run 时保存 papers/*.json，输出 merge_report.json
```

### 2.2 2025 年锚点匹配率

| 卷种 | 总题数 | 已答 | 锚点不匹配（pending） | 匹配率 |
|---|---|---|---|---|
| 市地 | 130 | 130 | 77 | 40.8% |
| 省级 | 135 | 135 | 81 | 40.0% |
| 执法 | 130 | 130 | 76 | 41.5% |
| **合计** | **395** | **395** | **234** | **40.8%** |

**锚点不匹配率高（~59%）的原因**：解析册的解析文本通常不直接引用题干原文，而是直接给出知识点讲解，导致题干前缀子串无法在 explanation 中找到。这是预期行为——锚点校验的设计目标是**拦截题号错位**（不匹配时进人工复核），而非要求 100% 匹配。当前策略是"锚点失败仍写入但标记"，平衡了自动化与安全性。

### 2.3 map_answers_2025.py 的跨卷匹配率

| 卷种 | 匹配数 | 未匹配 | 匹配率 |
|---|---|---|---|
| 省级 | 133/135 | 2 | 98.5% |
| 执法 | 129/130 | 1 | 99.2% |

未匹配的 3 题均为差异题（diff_book），解析内容与题干相似度低，需人工补录。

## 6. 答案接入完整 SOP

解析册到位后，按以下流程执行（以单年份为例）：

```
阶段 A：解析册预处理
  A1. 确认解析册格式（几套答案？是否分主卷+差异题？）
  A2. 扫描为 PDF（dpi≥150，A4 竖版，不斜拍不多页拼一张）
  A3. 先扫 2-3 页试跑，确认能稳定提取"题号+答案+解析"三件套

阶段 B：答案提取与映射
  B1. OCR/手动提取答案为原始 JSON（raw_*.json）
  B2. 如解析册为"主卷+差异题"格式，编写 map_answers_{year}.py：
      - 基准卷（通常市地）直接映射
      - 省级/执法通过题干相似度匹配基准卷答案
      - 未匹配到基准卷的，在差异题池中匹配
  B3. 如解析册为三卷独立答案，直接生成 answers_{paper}.json
  B4. 输出 answers_shengji.json / answers_shidi.json / answers_xzzf.json
      格式：[{number, answer, explanation, subtype, anchor_stem}]

阶段 C：锚点校验与合并（dry-run 先行）
  C1. python3 scripts/merge_answers.py --year YYYY --dry-run
  C2. 检查输出：
      - rejected > 0 → 答案格式错误，修正 answers_*.json
      - pending（锚点不匹配）→ 抽查确认是否题号错位，正常情况下 ~40-60%
      - 覆盖率是否符合预期
  C3. 确认无误后执行正式合并：
      python3 scripts/merge_answers.py --year YYYY --answer-source answer_book_YYYY-MM

阶段 D：验证与收尾
  D1. 运行 validate_papers.py 确认无新增错误
  D2. 抽查 10-20 题的 answer+explanation 是否与解析册一致
  D3. 缺页题/锚点不匹配题人工复核
  D4. 更新 EXTRACT_STATUS / catalog.json
  D5. git commit
```
