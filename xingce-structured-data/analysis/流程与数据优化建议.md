## 1. 整个流程优化

### 1.1 把「6 阶段流程」脚本化（解决 #3）

现状：`WORKFLOW.md` 描述的阶段 0–6 全部靠对话人工执行，不可复现、易遗漏。
建议：为每个阶段沉淀一个可重复执行的 Python 脚本，放 `scripts/` 目录（与数据分离，符合 AGENTS「临时脚本不入 artifacts」精神）：

```
scripts/
├── init_year.py        # 替代 init_year.sh，顺带生成标准 meta.json + EXTRACT_STATUS
├── extract_module.py   # 阶段2：按模块提取（含完整性校验，见 2.2）
├── assemble_papers.py  # 阶段3：组装三卷（含题号连续性校验）
├── map_diffs.py        # 阶段3.5：差异题映射（半自动，见 2.3）
├── media_crop.py       # 阶段4：整页/题级裁图 + media_index 生成
├── validate.py         # 阶段5：自动校验（见 1.3）
├── register.py         # 阶段6：自动更新 meta/catalog/DATA_STATUS
└── analyze/            # 数据分析脚本（见第 4 节）
```

### 1.2 统一断点续跑状态机（解决 #5）

`EXTRACT_STATUS.json` 应成为**每一年的标准产物**，字段统一为：

```json
{
  "year": 2024,
  "updated": "YYYY-MM-DD",
  "modules": { "政治理论": {"status":"done|partial|pending","file":"_extract/..."}, "..." },
  "pending": [],
  "summary": ""
}
```

- 每个脚本执行前读它、执行后写它，实现「中断后可接续」。
- 2025 补建该文件；2024 已有的按新结构归一。

### 1.3 校验自动化（解决「阶段5 是人工 checklist」）

`validate.py` 应自动输出、不靠人肉核对：

| 校验项 | 规则 |
|---|---|
| 题量 | `actual_question_count` == 官方题量（省 135 / 市地执法 130） |
| 题号连续 | 模块内 `number` 无跳号、无重复 |
| 无占位 | 无「待补全」题干（或已在 DATA_STATUS 登记） |
| 答案覆盖 | `answer` 非空占比（目标 100%，见 3.1） |
| 残缺题 | 检测「组合题/计数题缺条目」（见 2.2） |
| 媒体 | `media[].path` 对应文件真实存在 |

## 2. 解析方法优化

### 2.1 引入本地 OCR，减少纯人工视觉阅读（解决 #1 根因）

现状：扫描 PDF 无文字层，靠「渲染 PNG + 视觉模型逐题读」提取。成本高、且组合题的①②③④条目容易被截断漏读。

建议：
- 引入**本地可离线 OCR**（`RapidOCR` 或 `PaddleOCR`），先对渲染页跑一遍文字层提取，得到「可检索、可复制」的粗文本；
- 再用视觉模型对粗文本做「结构化纠错 + 题干/选项拆分」，而非从零读图；
- 组合题 / 计数题的「条目」是 OCR 最容易漏的短句，因此 OCR 后必须跑 2.2 的完整性校验兜底。

### 2.2 组合题 / 计数题完整性校验（解决 #1 直接）

解析规则：当题干以 `相符的有：`、`正确的有几项？`、`正确的有：` 结尾，但选项为 `①②` 组合或 `2项/3项/4项/5项` 时，说明**题干缺少 ①②③④ 条目正文**，应立即标记 `incomplete: true` 并回源补全。

建议在 `extract_module.py` 内置该检测，把「残缺题」在 `EXTRACT_STATUS` 里单列，杜绝静默入库。

### 2.3 差异题映射半自动化（解决 #6）

现状：差异卷开头的「注」靠人工读、人工对照。

建议：
- 先把「注」结构化成映射表：`{源卷题号 → 目标卷题号 → 原标注圈号}`，存 `_extract/diffs_map.json`；
- `map_diffs.py` 读映射表 + 差异题 JSON，自动做槽位替换，仅保留「无法判定」的少量题人工兜底；
- 目标：把 2024 shidi/xingzhengzhifa 从 125 补到官方 130。

### 2.4 双 pass 渲染策略固化

- Pass 1 结构扫描（40dpi）→ 定模块边界与题号体系；
- Pass 2 精读 + 裁图（100–150dpi）→ 提取题干/选项 + 图形/表格裁剪；
- 该策略已在 WORKFLOW 提到，建议写进脚本参数，避免每次人工决定。

## 3. 结果保存优化

### 3.1 补全 `answer` + `explanation`（解决 #2，最高优先级）

这是当前**最大的数据缺口**：全库题目只有题干+选项，没有答案与解析，导致「规律分析只能停在题型层面，无法做对错原理分析」，也无法生成模拟题的标准答案。

建议：
- 在 `_schema/conventions.md` 把 `answer`、`explanation` 从「可选」提升为「必填（或显式 `null` + 状态标记）」；
- 分模块补全（政治理论、马原答案唯一且权威，最易补；常识/判断次之）；
- 补全时同步写 `answer_source`（如「2025 官方解析」/「权威教材」），保证可溯源。

### 3.2 增加知识点标签字段（服务规律分析 + 模拟题生成）

现有 `subtype` 只到「削弱/加强」这种题型粒度，缺**考点粒度**标签。

建议新增两层标签：

```json
{
  "topic": "习近平新时代中国特色社会主义思想",   // 板块
  "tag":   "高质量发展·金融"                    // 专题（对齐规律分析 4.2 清单）
}
```

- 政治理论题尤其需要，因为「一题一专题」是模拟题生成去重的关键；
- `catalog.json` 同步记录各年「专题标签全集」，供跨年对比。

### 3.3 统一 schema + 加校验器（解决 #4）

- 为 `meta.json`、`papers/*.json`、`_extract/*.json`、`EXTRACT_STATUS.json` 各写一份 **JSON Schema**（放 `_schema/`）；
- `validate.py` 加载 schema 做结构性校验，从根上杜绝「2025 有 modules、2024 没有」这类漂移；
- 跨年字段以**最新（2025）为准**回填补齐，或写入 `conventions` 明确「可选字段」。

### 3.4 明确 `all_merged.json` 定位 + 溯源链

- `all_merged.json` 应明确为「**只读分析池**」，不参与三卷交付；生成规则写进 `conventions`。
- 补齐溯源：差异题保留 `original_number` + `source_note` + `source_file`，保证任何一题能追溯回原始 PDF。

## 4. 数据分析优化

### 4.1 分析脚本化（解决 #7）

把规律分析从「人工读 JSON」变为可复现脚本，放 `scripts/analyze/`：

| 脚本 | 产出 |
|---|---|
| `stat_modules.py` | 各模块题量、题型分布（判断/组合/计数占比） |
| `stat_asking.py` | 问法分布（正确/不正确/不属于/有几项…） |
| `stat_topics.py` | 考点专题分布（需 3.2 标签就绪） |
| `stat_distractors.py` | 干扰项手法标注统计（需人工/半自动标注干扰项类型） |

### 4.2 题库导出（衔接「日常学习训练」）

分析只是中间态，最终要「可用」。建议新增导出层：

- `export_excel.py` → 题库 xlsx（题干/选项/答案/解析/专题标签分列）；
- `export_anki.py` → Anki 卡片（政治理论 + 常识最适配闪卡记忆）；
- `export_md.py` → Markdown 题库（可进 Obsidian / 公众号素材）；
- 导出统一以「补全答案后的 `papers/*.json`」为唯一数据源，避免多份副本漂移。

### 4.3 跨年 / 跨卷对比

- 用 `stat_*` 脚本对比 2024 vs 2025 的模块题量、专题覆盖变化；
- 补 2023/2022 + 省考后，验证「政治理论 20 题 = 马原 20% + 习思想 80%」规律的稳定性，输出普适性结论。

### 4.4 与「政治理论文章 → 模拟题」方向的衔接

数据分析的终局是喂给模拟题生成管线：

- 输出「专题标签 + 题干引子（权威原句） + 干扰项手法」三要素库，作为生成 prompt 的确定性输入；
- 生成结果用 `validate.py` 反向校验（题型、题号、答案唯一、专题去重）。

## 5. 优先级与落地路径

| 优先级 | 事项 | 理由 |
|---|---|---|
| **P0** | 补 4 题残缺条目（回源扫描件） | 数据完整性，阻塞后续一切分析 |
| **P0** | 补 `answer` + `explanation`（至少政治理论 20 题） | 规律分析 → 对错原理、模拟题标准答案的前提 |
| **P1** | 脚本化：`init_year` / `extract_module`（含 2.2 校验）/ `validate` | 让流程可复现，杜绝再次漏条目 |
| **P1** | 统一 schema + JSON Schema 校验器 | 消除跨年漂移 |
| **P2** | 补 2024 差异题（125→130）、建 `EXTRACT_STATUS` | 补全年份完整度 |
| **P2** | 知识点标签 `topic`/`tag` + 分析脚本 + 题库导出 | 打通「分析 → 训练」闭环 |
| **P3** | 省考真题入库 + 模拟题生成管线 | 新方向正式落地 |

> 建议顺序：先 P0（把 2025 政治理论做成「带答案的干净题库」）→ 再 P1（脚本化，防止历史问题复发）→ 最后 P2/P3（扩展与闭环）。
